# Status paper: Constructor resilience

**Date:** 2026-08-18  
**Audience:** agents continuing coherence-cache work  
**Repo:** https://github.com/rivletio/constructor-resilience

---

## Abstract

**Constructor-resilience** is an open method for durable claims (*atoms*), consistency graphs, resilient *packets*, mint/critique/review, and query eval—a public package with a local MLX default (Qwen3-8B). Mint and critique stay offline. Packets are the share unit. Circle policy belongs to the host.

---

## 1. Where we are

### Constructor-resilience (method)

| Piece | State |
|-------|--------|
| Open package | `rivletio/constructor-resilience` on GitHub (MIT) |
| CLI | `coherence` — create/use topics, search, packet, intersect, export |
| Mint | Local MLX (`mlx-community/Qwen3-8B-4bit`); provenance on every claim; **grounding gate** drops inventions |
| Critique | Pre-human judge; `GATES`/`APPLIERS` dict dispatch; `--apply` auto-accept/reject on confidence + grounding |
| Review UI | `coherence review --serve` — accept / edit / reject + provenance + critique chips |
| Eval | Query-aware packets by default; on-topic ✓ / off-topic `INSUFFICIENT` |
| Config | `CoherenceConfig` + `COHERENCE_*` env (no scattered magic numbers in the happy path) |
| Interest / circles | Spec + intersect primitive; hosts enforce visibility |
| Agent skill | [`rivletio/constructor-resilience-skill`](https://github.com/rivletio/constructor-resilience-skill) |

Smoke (representative): grounded mint of source claims; critique auto-accept at high confidence; eval three on-topic queries and one off-topic control.

### What is *not* in this package

- Host UX (voice, TUI, glass) — adapters only; see `docs/HOSTS.md`  
- Auto-merge of gated `propose-seeds` output into any product YAML — human/CI gate only  

`coherence propose-seeds` emits gated NL→CLI proposals (`utterance_seed_proposals.json`); never auto-merges package YAML.

## 2. Architectural law (locked)

Packets explain and compress. They are not a command layer.

| | Execution | Knowledge |
|--|-----------|-----------|
| **Question** | What should we *run*? | What do we *believe* / explain? |
| **Artifact** | Host commands, maps, seeds | Atoms + packets |
| **Share unit** | Host-specific | `atoms.json` + `packet.json` |

**Law:** Hosts execute. Packets may explain, gate residual generation, or suggest a next step. They do not become the command layer.

## 3. Open questions

1. **Sufficiency on a query** — start lexical/query-overlap only, or add a tiny local classifier later?  
2. **Topic routing** — union of matching topics first; when do we zoom to one topic?  
3. **Seed growth loop** — should critique be allowed to *propose* utterance-seed rows, with human/CI gate?  
4. **Rust vs Python** — CLI can stay Python; a later host may port greedy/query-seed.
